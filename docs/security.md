# Security model

## Assets

User documents and transferred files (R2), link and request tokens, account sessions (Supabase), the database
(workspaces, links, audit log), and storage/database credentials (Railway variables only).

## Trust boundaries and controls

| Boundary               | Threat                                                                    | Control                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| ---------------------- | ------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Browser → API          | Forged or stolen session, CSRF                                            | Bearer token verified with Supabase on each request (30 s cache by digest); no auth cookies, so no CSRF; tokens are never logged                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| Browser → API          | Cross-tenant access, enumeration                                          | Every workspace call authorizes membership and role server-side; non-members get 404; strict schemas reject unknown fields                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| Page content           | XSS stealing the session (stored in localStorage)                         | Per-request nonce CSP with `strict-dynamic`, no `unsafe-inline`/`unsafe-eval` scripts, `connect-src` limited to self + Supabase + R2; React escaping, no `dangerouslySetInnerHTML`; `frame-ancestors 'none'`                                                                                                                                                                                                                                                                                                                                                                                     |
| Recipient → share link | Guessing links, password guessing                                         | HMAC-derived tokens (256-bit for share links and upload requests, 96-bit codes for confidential short links); scrypt-hashed passwords with per-link attempt lockout (each attempt is counted before it is checked, so parallel guesses cannot exceed it); per-IP rate limits on every public route, keyed on the address the trusted proxy appended (`TRUST_PROXY` hops), never a client-supplied one                                                                                                                                                                                            |
| Recipient → files      | Serving active content from our origin                                    | Files come only from R2 (separate origin) via short-lived signed URLs with forced `Content-Disposition` and `nosniff`; the app origin never serves user bytes                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| Uploads                | Malware, disguised file types, storage exhaustion                         | Quarantine until checked (type by magic bytes, structure, ClamAV); plan quotas enforced server-side before signing; unfinished anonymous uploads on one upload request are capped (count and reserved bytes) so a link holder cannot fill the owner's storage; a failed check rejects the file                                                                                                                                                                                                                                                                                                   |
| Short links            | Phishing redirects, open redirect                                         | Public links: http(s) destinations only (no `javascript:`/`data:`), operator-blocked hosts, abuse reports, operator suspension; confidential links resolve only to our own share/request pages; unlock page shows the destination host                                                                                                                                                                                                                                                                                                                                                           |
| App → Postgres         | SQL injection, over-privileged app                                        | Parameterized queries; private schema not exposed by Supabase's Data API; least-privilege role that owns nothing; append-only audit log                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| Team membership        | Being added to a team without consent, probing which emails have accounts | Members join only by accepting an invitation, signed in with the invited address confirmed; invitations expire after 7 days and lapse if the sender can no longer grant the role; the invite response is the same with or without an account; 30 invitations per hour per user                                                                                                                                                                                                                                                                                                                   |
| Custom domains         | Claiming a domain first to block its owner, keeping a lapsed domain       | Pending claims do not block anyone (unique only once verified); verified domains are re-checked daily and return to pending after the TXT record has been missing for 14 days, with warnings first                                                                                                                                                                                                                                                                                                                                                                                               |
| Operators              | Silent changes                                                            | Operator flag only via deployment tooling; plan changes and holds require a reason and write an audit event in the same transaction                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| Transfer emails        | Spam or phishing sent through our domain                                  | Sender must have a confirmed address (shown in the email and used as reply-to); at most 20 recipients per call and a monthly cap per plan (`emails_sent`, free: 300); fixed plain-text template with a report-abuse link; the message is the sender's own text, never HTML; sent by the worker with the job id as idempotency key                                                                                                                                                                                                                                                                |
| Download all           | Bypassing download limits                                                 | One archive request counts as one download against the link's limit (checked under the link row lock) and meters every file's bandwidth; URLs live 15 minutes and are signed per file                                                                                                                                                                                                                                                                                                                                                                                                            |
| Office conversion      | Abuse of the converter, malicious documents                               | Signed-in users with a confirmed email only; 50 MB cap enforced while reading; 6/minute and 100/day per user; type checked by name and magic bytes in the app and again in the converter. The converter is a separate private service (no public domain) that requires a ≥32-character shared token, runs each file in its own process group with CPU/memory/file-size limits, a timeout, a fresh temp directory deleted afterwards, as a non-root user; LibreOffice runs with macros disabled and linked/remote content blocked (tested); nothing is stored and names/contents are never logged |
| Android app → API      | Other sites reading API responses cross-origin                            | CORS is answered only for the app's WebView origin (`https://localhost`, `APP_ORIGINS`) and only on `GET /api/v1/config` and `POST /api/v1/convert/:target`; no credentials mode (bearer tokens, no cookies), so an allowed origin gains no ambient authority; every other origin, route or method gets no CORS headers and a 404 preflight (tested)                                                                                                                                                                                                                                             |
| Configuration          | Weak production setup                                                     | Startup fails closed: R2 required, strong `SHARING_SECRET`, HTTPS origins, ClamAV unless explicitly disabled                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |

## Honest limits (also shown to users)

- View-only access cannot stop screenshots, photos or copying. Revoking stops future access; it cannot recall copies.
- A short URL is not access control; confidential links rely on the share link's own protections.
- _Whiteout_ in the editor covers content visually; the text underneath remains in the file. It is not redaction.
- Names typed by recipients and submitters are unverified and labelled as such.
- Transfers accept common media and archive formats (MP4/MOV, MP3/WAV, PSD, 7z/RAR/GZ, Apple iWork…) checked by
  their content signature; these are download-only (never shown inline). Archives are not unpacked, so their
  contents are only as safe as the antivirus scan of the archive itself.
- Protect PDF uses AES-256. Print/copy/edit restrictions are enforced by PDF readers, not by cryptography; they
  do not stop screenshots or a determined user. A forgotten password cannot be recovered, and Unlock PDF only
  works with the current password.
- Signatures made in the editor are images placed on the page, not cryptographic (certificate) signatures.
- Office conversions (PDF ↔ Word, Excel, PowerPoint) are the exception: the file is sent to our converter, converted
  and deleted at once — the tool pages say so. A converted document is only as faithful as the layout analysis;
  check important documents. The converter can still reach the internet on Railway (egress cannot be switched off),
  so the LibreOffice hardening, not the network, is what stops documents from fetching remote content.
- Browser tools never upload files; a file handed from a tool page to the editor waits in this browser's IndexedDB for at
  most 10 minutes and is deleted when read.
- Session tokens live in browser storage (Supabase default); the CSP is the main XSS mitigation.

## Retention

- Temporary transfers: files are deleted at expiry (plan-limited retention); persistent transfers are kept until deleted.
- Upload requests: submitted files are deleted after the request's retention period, or with the request.
- Office conversions: nothing is kept — the file lives only in the converter's temporary directory for the length
  of the conversion.
- Abandoned uploads are cleaned up; R2 lifecycle aborts incomplete multipart uploads after 2 days.
- Cleanup never deletes an object still referenced by a version, transfer file, pending replacement or submission.
- Analytics are aggregate; detailed access events are kept for `EVENT_RETENTION_DAYS` (default 180).
- Licensing/plan problems degrade features; they never delete or lock user documents.

## Verification

`npm run check` (unit, API and security tests, including negative paths), `npm run test:approle` (same suite as the
least-privilege role), `npm run e2e` (real browser against a production build with the production CSP; set
`E2E_CONVERTER_URL`/`E2E_CONVERTER_TOKEN` to run the Office steps against a real converter instead of the stand-in),
and `cd converter && python3 -m unittest -v` (conversions, refusals, LibreOffice hardening, token and limits).
